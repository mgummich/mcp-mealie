Scope: local checkout, all 11 Python source files, unit/integration tests, dependency lock, packaging, CI/release workflows, scripts and documentation. No production Mealie instance was accessed. Security reproductions used mocked HTTP and dummy credentials. Findings are not fixes.

## Findings

### 1. High — Unvalidated path parameters escape the intended API endpoint

Location: `src/mealie_mcp/tools/recipes.py:157` (also other interpolated slug/item-ID paths).

`get_recipe(slug="../users/self", full=True)` issues an authenticated GET to `/api/users/self`, rather than a recipe endpoint. Confirmed through the actual FastMCP tool with respx: it returned the mocked user ID and email, including in read-only mode. HTTPX normalizes the interpolated dot segments. Equivalent construction exists in write tools.

Impact: an MCP caller can access backend endpoints outside the curated tool surface, within the Mealie token's existing permissions. This does not bypass Mealie authorization and does not itself prove a read-only write bypass. Risk matters when tool access is intended to be narrower than token access.

Fix: validate slugs and IDs as single path segments before constructing URLs. Reject dot segments, separators and URL control characters; apply appropriate segment encoding and central path validation. Add traversal tests for both reads and writes.

### 2. High — Source-link checker can probe internal network services

Location: `src/mealie_mcp/tools/library.py:225` and `:259`.

Stored recipe `orgURL` values are requested directly, with redirects enabled. `_probe()` accepts loopback URLs; mocked `http://127.0.0.1:12345/internal` was requested successfully. No scheme/address policy or redirect-destination validation exists. This tool is registered in read-only mode.

Impact: someone who controls a recipe source URL, or a redirect from that URL, can cause requests from the MCP host to loopback, private or link-local services when a user checks recipe links. HEAD can fall back to GET. Responses expose status/error information, not response bodies; Mealie credentials are correctly absent from this separate HTTP client.

Fix: enforce an outbound destination policy, including resolved addresses and every redirect. Allow intentional private recipe sites only through explicit configuration. Account for DNS rebinding in the connection design.

### 3. Medium — Cached recipe details can produce false cleanup guidance

Location: `src/mealie_mcp/client.py:379`, especially `:401`; consumer: `src/mealie_mcp/tools/library.py:92`.

Recipe detail cache has no TTL or externally accessible refresh. Only writes through this client invalidate it. Reproduction: fetch recipe with no ingredients, change the mocked backend response to include a food, then fetch again. Second call still returns no ingredients; backend request count remains one.

Impact: edits through Mealie's UI or another client are absent from food/unit usage reports until cache invalidation or restart. A newly used item can be reported as unused. Independently, capped/failed sweeps still label zero observed counts as `unused`, despite incomplete evidence; a note does not make those deletion candidates authoritative.

Fix: use TTL/version-aware refresh or expose a refresh option. Distinguish confirmed unused from unobserved items when a sweep is incomplete. Refresh taxonomy snapshots too: imports can introduce tags/categories without invalidating the name-resolution cache.

### 4. Medium — Invalid ingredient entries create unreported recipe stubs

Location: `src/mealie_mcp/tools/recipes.py:310`, `:118`, `:353`.

`ingredients: list[Any]` accepts values such as `[42]`. `create_recipe` creates the recipe before `_normalize_ingredient` calls `.get()` on that integer. The resulting `AttributeError` bypasses the handler that only catches `ToolError`.

Confirmed via actual MCP call: POST completed, then caller received `Error calling tool 'create_recipe': 'int' object has no attribute 'get'`, with no created slug or recovery guidance.

Impact: malformed model input leaves a partially created recipe and can encourage duplicate retries.

Fix: validate the complete ingredient structure before the first write, using a typed union/schema. Preserve the created slug in errors from any later population/readback failure. Avoid automatic rollback where it could delete useful partial data.

### 5. Medium — Meal-plan and cookbook lists cannot retrieve beyond 200 entries

Location: `src/mealie_mcp/tools/mealplan.py:49` and `src/mealie_mcp/tools/cookbooks.py:86`.

Both tools request a single `perPage=200` response. Neither exposes `page` or internally walks remaining pages. The shared formatter nevertheless instructs callers to pass `page=2`, which the tool schema rejects.

Impact: larger date ranges or cookbook libraries are incompletely accessible through these tools.

Fix: expose pagination or page internally with a documented result cap and usable continuation. Test with more than 200 entries.

### 6. Medium — Pagination hints continue after the last page

Location: `src/mealie_mcp/shape.py:305`.

The next-page decision compares total with the current page's item count, without accounting for offset/page size. Confirmed: total=3 and one item on page 2 produces `pass page=3 for more`. Empty later pages still advertise another page whenever total is positive.

Impact: agents following pagination hints can keep requesting empty pages indefinitely, wasting requests and tokens across search and taxonomy tools.

Fix: use backend pagination metadata or pass page size/offset into the formatter. Cover final full, final partial and empty pages.

## Additional project observations

- `src/mealie_mcp/server.py:28`: module-global client is shared by every `build_server()` instance. Concurrent servers in one process can route calls through the wrong configuration and interfere with cleanup. Normal single-server stdio deployment avoids this; use a closure/lifespan-scoped client before supporting multi-instance embedding.
- `src/mealie_mcp/tools/recipes.py:489`: image upload reads an entire caller-selected file synchronously, with only extension validation and no size cap. Add a regular-file/size check and bounded reading to prevent event-loop stalls or excessive memory use. Local image access is an intentional feature, not by itself a secret-exfiltration finding.
- `SECURITY.md:5` is an unfilled template: support versions 5.1.x/4.0.x do not describe this 0.3.1 project, and reporting instructions are placeholders.
- `tests/integration/compose.yml:7` publishes the disposable service on all interfaces while tests authenticate with default credentials. Bind the port to loopback.
- CI has useful Python 3.11–3.13 checks and CodeQL, but no dependency vulnerability scan. Release gates omit formatting, mypy and live integration checks. Action references use mutable tags; consider immutable commit pins and explicit least-privilege workflow permissions.
- Runtime requirements have open lower bounds (`fastmcp>=2.10`, etc.). Git-tag installation pins application source, not the resolved dependency graph. The checked lock is healthy per this scan; supported dependency minima are not exercised by the test matrix.
- Existing integration tests cover common round trips against Mealie 2.8.0. They do not establish compatibility across the full documented Mealie 2.0+ range, or cover security boundaries, larger pagination, external cache updates or all partial-write failures.
